## Resolution log (2026-08-13)

All 28 flagged fields reviewed against their source `.md` files and resolved. Draft schemas updated in place.

1. **~19 "optional but gives a fallback instruction" fields** (across book, content_marketing_strategy, funnel_hub_media, lead_magnet-adjacent, plan_of_action, social_content_strategy_audit, offers v1/v2): confirmed against source text in every case. Resolution: kept `required: false`, added a new `fallback_instruction` field carrying the exact inference/default text from the source `.md`, so the Prompt Assembler can inject it when the field is left blank. No new `kind` needed.

2. **`regulated_field_flag`** (lead_magnet, plan_of_action, offers v1 — formerly value_ladder_genie): source confirms "if yes, name the regulation." Resolution: added `"conditional_children": ["regulation_name"]` to the flag field and synthesized a new `regulation_name` text field with `"conditional_on": {"field": "regulated_field_flag", "equals": true}` — matching the worked example already in `Conversational_Intake_Engine_Design.md` §4 exactly.

3. **`target_service_offer_to_ladder`** (offers v1 and v2): source is explicit — "REQUIRED for Wish 6, optional for other Wishes." The existing taxonomy (`kind`, `conditional_on`) only covers conditional *visibility*, not conditional *requirement*. **Taxonomy extension**: added a new `required_if` key — `{"field": "wish_mode", "equals": "Wish 6 (Single Offer Type Laddered)"}` — read by the Validation Gate as "required only when this condition holds, else optional." Flagging for whoever builds the Validation Gate (Day 4-6) to implement this key alongside `required`/`conditional_on`.

4. **`financial_anchor_inputs`** (offers v1): all 3 sub-fields confirmed optional in source (two say "leave blank", currency defaults to USD) — parent compound field's `required` flipped from `true` to `false`.

5. **Terminology map fields** (offers v2: `word_for_the_buyer`, `word_for_the_offer_unit`, `word_for_the_first_commitment_step`): section header states "optional — leave blank to derive from the ICP, CRO framework, or Industry" — kept `required: false`, added that text as each field's `fallback_instruction` for clarity, since the optionality was inherited from the header rather than stated per-field.

6. **Duplicate "Offers" asset** (`value_ladder_genie` vs `value_ladder_universal_v2`): confirmed via source inspection that `Master_Prompt_Universal_Value_Ladder_v2.md` is explicitly "Value Ladder Genie (v2.0)" — a generalized successor, not a distinct asset. **User decision**: unify under one asset, using the versioning `field_schema_registry(asset_id, version, ...)` already supports. Files renamed: `value_ladder_genie.json` → `offers_v1.json` (`asset_id: "offers", version: 1`), `value_ladder_universal_v2.json` → `offers_v2.json` (`asset_id: "offers", version: 2`). New runs should default to `version: 2` (latest); `version: 1` stays queryable for reproducing older runs.
